# Tibo 全部新动态的中文微信与邮件通知

本分支将 Tibo（`@thsottiaux`）自己发布的全部新帖子和回复发送为中文微信通知及邮件，不再只匹配 reset。保留英文原文、原帖链接和北京时间；图片以远程 HTTPS 图片引用展示，不分析或翻译图片中的文字。转发他人的内容仍按上游来源规则排除。

## GitHub Actions Secrets

在仓库 Settings → Secrets and variables → Actions 中填写：

| 名称 | 内容 |
| --- | --- |
| `SMTP_USER` | Gmail 发件邮箱 |
| `SMTP_PASSWORD` | Gmail 应用专用密码，不能使用 Google 登录密码 |
| `EMAIL_FROM` | 同一个 Gmail 发件邮箱 |
| `EMAIL_TO` | 目标收件邮箱 |
| `PUSHPLUS_TOKEN` | 可选，PushPlus 用户或消息令牌；不填则不启用微信 |

邮箱地址和密码都保存在 Secrets 中，不写入公开源码。SMTP 默认使用 `smtp.gmail.com:465` 的 TLS 连接。翻译仅向 Google Translate 网页翻译接口传输公开帖子的正文，不传输邮箱凭据。该翻译入口和 FxEmbed 均为第三方依赖；失败会保留待发送消息，在下次运行重试。

## 添加个人微信通知

1. 在 [PushPlus 官网](https://www.pushplus.plus/login.html) 用自己的微信扫码登录，完成实名认证，并关注或绑定公众号。实名信息仅在官网填写。
2. 在“一对一消息”页面复制自己的令牌，直接添加到当前 GitHub 仓库的 Actions Secret `PUSHPLUS_TOKEN`，不要粘贴到聊天、源码、Issue 或日志。
3. 运行下述工作流，勾选微信测试选项。到 PushPlus 消息记录核对最终发送结果，再确认手机微信收到中文内容。

微信使用 HTTPS POST，将令牌放在请求体中；不设置群组或好友收件人，只发给令牌所属用户。令牌本身不进入监测状态，仅保存目标身份的哈希。邮件和微信复用当次翻译结果。

免费实名用户的微信额度目前为每日约200次请求、每分钟5次，以 [官方额度说明](https://www.pushplus.plus/doc/guide/use.html) 为准。每次监测最多尝试4条微信请求，其余消息留待下轮；失败请求同样可能计入额度。超过每日额度后不能保证当天全部动态通过微信送达，邮件仍独立发送。超长微信正文会明确标注为节选，并保留完整原帖链接；邮件保留全文。

PushPlus 的 `code=200` 和流水号只表示服务端已接受请求，不能证明微信已送达；最终状态需在官网记录或微信端核对。当前队列在收到有效受理回执后记为该渠道完成，不自动查询异步投递状态。接口拒绝、网络或翻译失败则保留待重试记录。投递状态不明、或受理后 GitHub 状态未成功保存时可能重复通知。

## 运行与验证

运行工作流“Tibo 中文微信与邮件通知”，可分别勾选“发送一封最新真实帖子的中文测试邮件”或“向自己的微信发送一条最新真实帖子的中文测试通知”，使用最新已抓取的真实帖子验证链路。首次监测只建立最新游标，避免一次性补发历史消息。新增微信目标也只接收启用后新入队的动态；不会自动补发之前已完成的邮件。

默认每五分钟检查一次。GitHub 排队、数据源缓存和邮件投递均可能造成额外延迟，不能保证秒级或绝对不漏。读取和发送断点持久化到独立 `monitor-state` 分支；每个目标成功发送后保存状态。SMTP 在服务端已接受但客户端断线、或服务端接受后 GitHub 状态未保存时，重试可能造成重复邮件；固定 Message-ID 有助于邮箱归并，但不能保证服务端幂等。
